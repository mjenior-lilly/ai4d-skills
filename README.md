# AI4D - Skills

My personal prompt library for work within the AI4Discovery group across LLM harnesses.

The repository contains operational prompts for software delivery, research, knowledge management, teaching, document summarization, benchmark generation and evaluation, and technical-paper presentation. Most prompts assume access to real repository context such as code, tests, diffs, plans, logs, and shell tools.

## Repository layout

Each content directory listed below has a README with its inventory and usage details.

### [`commands/`](commands/README.md)

Explicit slash command-style prompts for bounded or intentionally stateful tasks:

- investigation and audits: `/investigate-issue`, `/test-audit`, `/slop-search`
- planning and implementation: `/create-plan`, `/cross-examine`, `/implement-plan`, `/audit-implementation`
- repository and benchmark artifacts: `/create-test-dataset`, `/map-repository`
- documentation and communication: `/annotate-code`, `/humanize-text`, `/write-branch-mr`, `/agent-handoff`
- branch-to-pull-request execution: `/yeet`

### [`skills/`](skills/README.md)

Reusable procedures selected from natural-language intent or explicitly loaded by a harness. Single-file skills cover external repository exploration and subagent delegation. Multi-file skills cover two-axis code review, Obsidian knowledge graphs, deep research, stateful teaching, and structured document summarization. `simplification-audit-to-pr.md` is a standalone, evidence-gated workflow definition for taking a broad repository audit through planning, implementation, verification, and an optionally authorized PR or MR.

### [`agents/`](agents/README.md)

Session-level system prompts:

- `SYSTEM.md` defines the operating policy for a direct CLI coding agent.
- `judge.md` evaluates model responses against corpus-grounded benchmark entries generated by `commands/create-test-dataset.md`.

## Common principles

The library consistently favors:

- evidence-first reasoning over speculation
- repository inspection before proposing changes or abstractions
- explicit scope and authority boundaries
- minimal, contract-consistent changes
- verification through realistic checks
- clear separation between read-only review and mutating execution
- direct output formats intended for practical use

## Choosing commands and skills

Use a command when the workflow should be invoked explicitly, has exact invocation semantics, or performs high-risk and stateful actions. Use a skill when the procedure recurs across conversations and benefits from intent-based routing.

The current command and skill inventories do not duplicate the same capability. `commands/yeet.md` remains command-only because it can create a branch, stage and commit files, push, and open a pull request. `commands/agent-handoff.md` also has no skill counterpart because it creates an explicitly requested, redacted handoff in the operating system's temporary directory.
